# Ren’Py 新引擎与云存档

新引擎使用独立的本机工作区和云端档案。默认入口继续使用原引擎；播放器中的“使用新版引擎（独立存档）”切换到登记过兼容关系的发布版本。运行中切换也经过保存退出屏障。

## 使用流程

1. 在原引擎内保存并退出，手动上传原云档。
2. 切到新版引擎，在存档管理中选择一条原引擎云端历史，点击“复制原引擎云档到新版工作区”。原档案、head、本机原工作区和历史不变。
3. 新版引擎读档后正常游玩、保存并退出，再手动上传到新版独立云档。
4. 另一设备选择相同新版引擎，登录后从其独立云端历史恢复。原生游戏槽位需要在游戏菜单内读取。
5. “切回原引擎”重新打开原工作区；不会清理新版进度。不会自动把新版文件覆盖到原工作区。

账号页可分别选择原引擎和新版独立档案，下载、恢复云端历史和发布分享。分享冻结实际引擎发布 ID；领取时进入相同发布的独立档案，不覆盖接收者原引擎 head。引擎身份只是兼容范围的一部分，不能保证未测版本或未来任意存档可读取。

## 契约与部署

- v1 云包的 `engine` 指纹和既有字节契约保持；v2 `wvn-engine-cloud` 显式记录 `releaseId`、`saveCompatibilityId`，不冒用旧 `engine`。不同版本或发布的包不能直接互读。显式旧档复制先按原 v1 身份验证。
- 新 scope 在存档服务内部编码为 `["wvn-engine-cloud-v2", versionId, releaseId]`，沿用原唯一索引。对外的 `versionId` 和网站路径不变，额外返回 `engineReleaseId`。旧查询继续只读原档案。额度、账号删除、备份和所有权检查覆盖全部档案。
- 本机历史记录当前运行区的 `runtimeReleaseId`。云端待上传队列及同步基线也按发布分 scope；旧队列和旧两字段 link key 不迁移。
- `WG_ENGINE_RUNTIME_FILE` 是管理员提供的兼容登记，`cloud-testing` 只允许独立预览；`verified` 需每个版本的双向原生证明及完整云端证明。回执以 SHA256 固定。未登记候选仍禁止生产并关闭云端。
- 正常回退优先关闭新版绑定，保留理解新 scope 的账号服务。若必须回退到此前旧代码，新版档案可能在旧账号页显示为未知版本；不能回灌旧数据库，更不能为让旧客户端读取而改写新版包的标签。全部文件与历史保留，重新部署当前账号服务后恢复显示。

预览与生产是不同来源，凭据和浏览器存档不会自动迁移。兼容验收使用独立合成账号，并在结束时重新验证通行密钥后清理；真实用户数据不参与验收写入。

### 远程验收接续

当原构建机无法及时返回文件时，可使用登记的 Arch 临时浏览器容器接续。主机保护只允许原构建目录或专用容器的 `/work`；预览来源固定为 `https://localhost:18601`，容器仅允许单并发。容器使用已有代理下载浏览器，限制 CPU、内存及缓存，不挂载生产数据。

缺失夹具通过原引擎进入真实正文并原生保存重新生成，再由新引擎实际读取、推进、另存；云包、跨浏览器恢复、真实进程重启和原浏览器回退的断言保持。完整子回执、父进度回执及原始工具输出按来源分别归档，摘要不能混用。卡住的旧矩阵不整体记为成功，合成账号清理单独核对。

Arch 补验收时，备份/分享单元测试仅在各自临时夹具目录模拟可用空间；真实目录和生产 62 GiB 保护不变。SDK 失败日志用例在非登记主机上断言真实的主机保护错误，登记构建机继续验证残留安装检查。
