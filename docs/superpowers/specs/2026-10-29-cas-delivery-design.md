# 游戏 CAS 加载与旧对象清理

用户要求先让游戏实际读取 SHA-256 `.bin` 对象，验收通过后清理旧文件。沿用已确认的服务边界和直接实施方式，省略设计审批。

实施选择由实现者作出：保留现有游戏虚拟 URL 和相对路径，CDN Worker 从公开 PG 资源 API 获取不可变映射，再只向固定 B2 源请求根目录 `{sha256}.bin`。冷映射需要一次主站查询，边缘只缓存经过完整验证的公开元数据。相比逐引擎重写成裸哈希 URL，此方案保留相对引用与 MIME；相比另建全量 KV/静态索引，此方案复用已经上线的 PG 权威映射。

新增 `GET /api/resources/by-path?namespace=...&path=...`，仅查询已发布快照，返回既有 `{key,url,sha256,bytes,contentType}` 或 404。Worker 命名空间固定为 `b2/web-visual-novel/snapshot-20261028`，API 源固定为 `https://wg.saop.cc`，B2 源固定为 `https://f003.backblazeb2.com/file/web-visual-novel`，不得接收任意上游、转发浏览器凭据或回退旧对象。原路径仅用于查映射和保留 MIME/相对引用，实际 B2 读取 URL 必须以完整 64 位小写十六进制摘要加 `.bin` 结束。

小对象保留完整缓存填充、断流重试；大对象保留流式下载。GET/HEAD/Range、If-Range/条件请求、CORS/CORP、脚本/WASM/HTML 安全策略不得回归。缓存采用新版本键，防止旧正文命中掩盖映射遗漏。诊断头明确给出实际 CAS key 和原路径。

清理仅针对 `web-visual-novel` 公共桶。先只读列举并对齐冻结源 SQLite 与当前 PG 映射，生成带确切文件名、版本 ID、目标 SHA-256、大小、源/目标摘要的清单。仅删除已经证明由已核验 CAS 对象承接的旧版本；任何未知、变更或缺目标版本均停止并单独列出。禁止按“非 .bin”或前缀批量盲删、禁止创建删除标记代替确切版本删除、禁止删除 CAS 对象、账号数据或私有存档。

删除门槛：代码与测试审阅完成；全量目标与映射一致；全部 79 个版本及固定引擎/媒体路径的 HTTP/MIME/Range 核验通过；ONS、Artemis、Tyrano、RenPy 的真实浏览器冷启动与重进通过且实际来源为 CAS；公网切换后再次验证。满足门槛后，按用户本次授权先执行受控小批并核对，再分批断点清理清单内旧版本，最后重新列举及复验游戏。保留 PG/SQLite 映射、删除审计和切换前配置，删除后不能回退到依赖旧对象的 Worker。
