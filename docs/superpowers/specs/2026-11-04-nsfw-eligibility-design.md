# NSFW 分级与站内浏览资格设计

日期：2026-11-04（Asia/Shanghai）

状态：设计草案；用户已选定“登录＋规则理解测试”方向，具体规则参数为下文建议，尚未开发、部署或修改生产数据。

独立设计审阅已完成，未发现制定实施计划前必须澄清的重要未决项；这不代表用户已批准全部细节或已经完成产品验收。

## 1. 已确认的目标与边界

用户希望参考 KUNGal 等 Galgame / VN 站点区分 NSFW 内容，并明确选择：

- 不适合公共场合展示的内容，必须登录并通过规则理解测试，取得资格后才可切换显示。
- 资格属于站内浏览权限，不宣称已验证成年，不评价“成年心智”或心理健康。

本方案建议沿用统一作品目录，将页面适宜性、实际游玩版本、单张图片分别分类。SFW 页面可以介绍含成人版本的作品；成人版本启动仍需相应浏览资格。

本次交付是设计文档。下列题数、重试规则、状态与接口名称均为设计建议，并非用户逐项确认的要求。正式实现、远程验证、推送与部署属于后续工作。

### 不包含的工作

- 身份核验、真实年龄核验、心理测评、人格或智力评估。
- 对读者提供心理诊断、成熟度分数或类似结论。
- 新建成人子站或拆分作品身份、版本编号、存档归属。
- 修改现有游戏字节、公开 CAS 对象、资源域名、缓存基础设施或引入 Worker。
- 声称能够阻止已经持有公开哈希地址、资源副本或浏览器缓存的人访问这些字节。

## 2. 参考与方案选择

已核对的公开依据：

- [KUNGal 对 SFW 含义的解释](https://www.kungal.com/topic/2462)：页面 SFW/NSFW 不代表游戏是否包含成人内容。
- [KUNGal 现有引擎目录](https://www.kungal.com/galgame/engine/2)：默认 SFW，提示部分条目因显示设置而隐藏。
- [鲲 Galgame 补丁的说明](https://www.moyu.moe/doc/notice/nsfw)：标题、封面、介绍和标签均影响页面适宜性；其无需登录的切换方式不采用。
- [VNDB 官方 API](https://api.vndb.org/kana)：图片性内容与暴力评分、评分票数，以及发行版的年龄分级和 `has_ero` 分开提供。
- [TouchGal 官方 API](https://developer.touchgal.com/docs/api)：搜索、详情、资源、补丁接口统一应用 SFW/NSFW 条件。
- [itch.io 发布指南](https://itch.io/docs/creators/quality-guidelines#adult-content-must-be-labeled)：成人内容需标注，并避免露骨封面。
- [APA 测评指南](https://www.apa.org/about/policy/guidelines-psychological-assessment-evaluation.pdf)：测评解释须有适用于具体用途的效度依据。本设计不把自编规则题解释为心理测评。

考虑过的方案：

1. **游客直接切换 NSFW**：交互最轻，但不能满足用户已确认的登录、答题要求，因此不采用。
2. **登录＋规则理解测试＋主动切换**：用户选定；资格可管理、撤销，测试内容可解释，适合作为站内准入门槛。
3. **年龄核验＋规则测试**：用于不同目标，需要额外的数据处理与服务选择；用户本次没有选择，不纳入实现范围。

推荐保留一个目录。默认隐藏所有含成人版本的作品会连带隐藏安全的作品资料和其他版本；拆分成人专区会增加多版本归属、搜索与收藏维护成本。

## 3. 当前项目情况

本地仓库静态快照为 72 部作品、94 个版本、384 张封面及截图；这是仓库数据，不代表已核对生产数据库。

- `scripts/prepare-metadata.ts` 会筛选性内容、暴力评分均为 0 的 VNDB 图片，并有替代封面和 Bangumi 分支；现有数据不能因此整体视为已人工审核。
- `src/metadata.ts` 未保留逐图内容评分与票数；现有 `ratings` 是作品口碑评分，不能复用为内容分级。
- `src/types.ts` 的作品与版本没有内容分类；版本 `published / hidden / deleted` 是生命周期，不应承担 NSFW 分类。
- 目录、搜索、继续阅读、作品页、存档分享分别投影内容，当前没有共同的浏览资格判断。
- 账号已有 Passkey 会话、设备撤销、账号切换失效处理；Passkey 登录不代表年龄核验。
- 公开目录、图片、播放器资源清单和部分兼容入口目前允许匿名读取；不能只在 UI 上锁开关。

## 4. 三层内容分类

### 4.1 页面适宜性

作品记录 `pageSuitability = sfw | nsfw | unknown`，附判定原因、来源、核实时间与修订号。

- 判断范围为正常打开页面会直接展示的标题、封面、简介、标签、别名和其他文案。
- 只更换封面不能自动把页面改为 SFW；露骨标题或介绍同样可以使页面成为 NSFW。
- 已明确标记并默认不加载的敏感图库单独受控，不必使安全的文字资料页整体成为 NSFW。
- 如需整理公共简介，保存人工整理的文本与来源标记，不通过临时关键词替换伪造“安全简介”。
- `unknown` 不进入公开发现列表；管理员审核后才可进入相应范围。上线前先完成现有可见页面的分类，不能直接把全部旧条目批量隐藏或批量标安全。

### 4.2 游玩版本

版本记录 `sexualContent = none | present | unknown`，并可保存有来源的 `ageRating`、对应发行版及其他内容警示。

- `none` 只表示经核实不含成人性内容，不自动表示适合所有年龄。
- “全年龄版”“R18”等标签必须有与本站实际版本相符的证据。
- 同一作品可包含不同分类的多个版本，不从原作某个发行版推断所有本站版本。
- 暴力、恐怖等警示另存，不把性内容和所有成人主题混成一个字段。
- `present` 的启动入口要求资格及当前会话开启；`unknown` 按受限启动处理，并明确显示“内容待核实”。
- 页面可公开而版本受限时，公开投影可显示已审核的中性版本名称和内容标记，不返回启动清单及资源地址。未审核的版本标题只显示“版本 N · 受限”。
- 默认阅读按钮优先选择已发布、内容已核实且当前可启动的版本，再沿用已有默认版本与排序规则；只有受限版本时展示“取得资格后阅读”，不静默跳入。

### 4.3 单张图片与分享文案

图片分别记录性内容、暴力与剧透标记，内容等级均允许 `unknown`，附来源、票数及人工覆盖记录。

- VNDB 分数是 0–2 的平均值，可能为小数；保留原始分数与票数，不能当作三个整数枚举或忽略无票情况。
- 首版自动通过条件建议为两个分数均为 0 且有评分票；无票、缺字段、其他来源及冲突素材转人工审核。人工审核可提供明确的覆盖结果。
- 首版只展示已核实安全图片，不因启用 NSFW 就自动导入上游敏感图库。
- 后续引入敏感图库时，必须使用受控素材接口；未展开前不下发原图 URL、不预加载图片，以不透明占位提供“查看此图 / 收起”。
- 剧透与 NSFW 分开判断；查看敏感图片也不能自动展开剧透。
- 存档分享的标题与说明单独审核：游戏版本为非成人，也可能有 NSFW 分享文案。游戏为成人版，也不要求所有中性存档说明都默认展开敏感内容。

## 5. 资格与显示模式

### 5.1 资格属于账号

状态建议为 `unqualified / qualified / suspended / needs_retest`：

- 初始为 `unqualified`；提交有效测试并通过后为 `qualified`。
- 核心规则版本改变而必须重测时为 `needs_retest`；普通文案勘误不强制所有人重测。
- 管理员可暂停或撤销资格，记录理由；`suspended` 不能靠重测自行恢复，需先解除暂停。
- 资格默认不按固定天数过期；注销账号时随账号删除，资格不随链接、导出文件或另一个账号转移。

### 5.2 模式属于当前认证会话

`displayMode = public | restricted`，新会话默认 `public`。

- 新设备、新登录会话、退出后重登均需主动开启；账号资格仍保留，无需重复答题。
- 同一有效会话刷新页面可以保持模式；账号切换不得继承上一账号的显示模式。
- `restricted` 的写入由服务端在检查资格后处理，不信任 URL 参数、localStorage 或可伪造的开关值作为授权依据。
- 资格有效不等于已开启；每次受限请求都判断会话、当前资格及模式。

准入关系为：**有效登录会话 ＋ 当前规则版本资格有效 ＋ 当前会话主动开启**。

### 5.3 失效与运行中的播放器

- 切回公共浏览、退出、设备撤销、资格撤销及账号切换后，前端同步遮挡敏感内容，不等待下一次页面刷新。
- 每次新请求在服务端重新判断；已有标签页通过账号失效事件及跨标签页通知同步，并在重新聚焦时复查。
- 运行中的受限游戏先遮挡并停止继续操作、静音，能暂停则暂停；不能保证所有引擎后台时钟均暂停。
- 不自动销毁实例或删除存档。提供重新登录/开启模式后继续，以及尽力保存到本机后退出的路径；会话失效时不得承诺云保存一定成功。
- 已交付客户端的字节不能收回；下文的公开 CAS 边界仍适用。

## 6. 规则理解测试

名称为“敏感内容浏览资格测试”。入口明确说明：测试只确认对本站规则的理解，不验证年龄、不提供心理评价。

### 建议参数

- 初版题库 12 题，每次 8 题：4 道核心规则题必选，另随机抽取 4 题，选项顺序可打乱。
- 全部答对通过；提交前可返回修改，不设置倒计时或以阅读速度判失败。
- 每次未通过提供错题对应的规则解释，可返回阅读规则；不显示成熟度、人格或心理健康结论。
- 每账号最多提交 3 次 / 滚动 24 小时；未通过后冷却 30 分钟，页面显示可重试时间。会话或网络错误不占失败次数。
- 题目签发后 24 小时内可提交；到期只需换题，不记为失败。滚动刷新不能规避已提交次数。
- 同一账号一次只允许一个有效测试；并发提交、双击、网络重试采用同一提交结果，不能重复扣次数或重复授予资格。
- 提交时规则版本已变化则重新出题，不对过期规则授予资格，也不记失败。

这些参数控制随意跳过与频繁请求，不是防未成年人保证。题目公开、讲解清楚符合教学目标，不依赖隐藏规则或难题来推测年龄。

### 核心题示例

1. **作品页标 SFW，是否证明其中所有版本都是全年龄？** 正确理解：需要查看具体版本的内容标记。
2. **游戏中的虚构描写，是否等于现实中的行为许可？** 正确理解：不等于；现实行为仍需要尊重他人的同意与边界。
3. **已取得资格，能否把敏感图片直接发到公共区域？** 正确理解：不能，公开发布仍受内容规则约束。
4. **内容引发不适时是否必须继续阅读？** 正确理解：可以停止、屏蔽或举报，无需完成阅读。

其他题覆盖账号不出借、尊重他人的显示偏好、剧透和 NSFW 的区别、举报与退出入口。

题库不包括心理病史、性经历、创伤经历、性取向、人格倾向，也不靠年代梗、Gal 知识、学历或文化背景判断资格。支持键盘、屏幕阅读器和手机作答。

## 7. 页面与入口行为

### 游客及未取得资格者

- 导航显示“公共浏览”；点击受限模式进入登录或测试说明。
- 首页、搜索、标签、继续阅读、收藏展示按同一策略投影。对被隐藏条目给统一提示，不泄露未经审核的标题、别名、封面或简介。
- 深链接显示中性的资格提示与下一步操作，保留站内目标路径；登录、答题、主动开启后可返回。返回地址只接受本站相对路径。
- 受限提示页的网页标题、description、分享预览和首屏数据也必须中性，使用 `noindex`；不把完整数据先写入页面再靠 CSS 遮住。
- 同一公开作品下允许展示安全的版本摘要，但受限版本不能返回启动资源清单。

### 已取得资格但未开启

- 保持与公共浏览相同的输出。导航显示“已取得资格”，提供主动开启操作，不自动切换。
- 开启前简要说明当前设备将展示敏感内容，提供明确取消与开启按钮。

### 已开启

- 可发现和打开已审核的 NSFW 页面，卡片有文字标记，不只依靠颜色。
- 内容筛选提供“全部可见版本 / 已确认不含成人性内容 / 含成人性内容 / 待核实”。只保留匹配版本，作品卡片版本数与阅读目标随筛选一致。
- 成人版本启动前展示具体版本的内容提示与“开始阅读”；此提示不另行签发资格。
- 所有模式下首版均使用安全封面；“显示全部”不意味着主动展开敏感图库或剧透。

### 个人存档与分享

- 公共发现、公开分享与链接分享的文案适用相同浏览规则；持有分享链接不自动获得资格。
- 敏感分享的公开投影先返回中性受限状态，不能只在作品页隐藏，而在独立分享页直接展示。
- 私人云存档、账号导出、恢复与删除能力不因浏览资格丧失而被剥夺。公共模式下个人列表可显示中性占位及原有备份操作，不直接展开敏感名称或说明。
- 关闭显示模式只改变展示，不从收藏、书架或数据库删除条目，也不删除本机阅读记录。

## 8. 服务端设计建议

### 8.1 统一判定

建立请求级内容策略上下文，区分匿名、已登录、资格状态及会话显示模式。页面 loader、目录投影、搜索、分享和启动入口复用同一判定，不各自拼布尔值。

- 账号服务是资格和会话模式的权威；目录服务通过可信服务边界取得经过验证的上下文，不能把客户端 `userId` 或自报资格当事实。
- 如果服务分进程，服务间采用当前会话的内部校验接口，并以独立服务凭据认证；凭据不返回浏览器。内部请求不能接受任意客户端注入的资格响应。
- 同一请求内可去重资格查询；首版不跨请求缓存正向授权，避免撤销资格后还沿用旧结果。
- 必需的身份或资格查询失败时，受限请求返回暂不可用，不回退为已获资格；纯公共目录仍可使用。
- 页面数据、公开目录 API、搜索结果、总数、标签聚合和分页采用同一可见性。Meilisearch 先过滤候选，再由当前数据库分类复核，防止旧索引继续展示条目。
- `recentWorks` 等辅助投影也必须过滤，不能返回全目录供客户端自行决定展示。

### 8.2 接口建议

最终接口命名由实现者沿用现有路由惯例；以下描述语义：

- 查询我的内容权限：返回资格状态、所需规则版本、当前模式及下次可重试时间。
- 创建测试：必须登录，服务端签发题目、选项、尝试 ID 与版本，不下发用于判分的正确答案字段。
- 提交测试：只接受尝试 ID 与选项 ID，服务端判分、限次及原子授予资格，不接受客户端分数或 `passed`。
- 更新显示模式：必须校验会话绑定与来源；开启须具备资格，关闭可随时执行。
- 管理资格：复用私有管理边界；暂停、解除暂停、要求重测均留理由及审计记录。

受限 API 的错误语义建议为：未登录 `401`；未取得资格、需重测、被暂停、未开启分别以稳定错误码返回 `403`；依赖不可用 `503`。公共列表正常过滤并返回 `200`，而不是因存在被隐藏条目就整页报错。

### 8.3 内部目录不得依赖匿名展示结果

现有账号 `catalogProvider`、分享和资源映射使用公开目录作为内部资料来源。给 `/api/catalog` 加匿名过滤后，不能让内部服务误判受限版本已删除。

应提供不暴露给公众的可信目录读取能力，保留完整内部版本归属；输出给用户时再按其请求上下文投影。管理后台的生命周期权限与读者资格分离，不对后台审核流程套用公开列表过滤。

### 8.4 公开 CAS 与素材边界

遵守已有[浏览器直连 CAS 设计](2026-10-29-cas-browser-direct-design.md)：服务端承担元数据、启动与清单控制，浏览器直连既有公开 SHA256 对象；本方案不增加 Worker、正文代理或改变对象存储。

- 对站内受限播放器启动、可信启动 HTML 和资源清单 API 检查资格；对版本资源清单、逻辑路径查询及兼容入口进行完整枚举，避免通过另一条站内元数据接口取得同等清单。
- 通用公共资源索引若仍能匿名列出全部游戏映射，必须先为本站应用相关映射加入相同可见性或迁至内部接口，不能在验收中遗漏这一点。
- 已存在的公开哈希对象和已取得的资源副本无法由站内资格收回；公共仓库中已有的静态登记、标题和公开来源资料也不转为秘密。
- 首版不新增敏感图片。后续敏感图库不应上传至当前无资格检查的 `/media/` 路径；必须从入口到正文响应都验证权限。
- 若用户以后要求所有游戏字节直链也必须鉴权，这是资源架构变更，需要另行设计和授权，不能在本功能内暗中改造。

### 8.5 缓存与日志

- 首版所有带资格差异的页面与 API 使用 `private, no-store`；共享缓存只允许明确不含个人状态的公共投影。
- 退出或关模式时清理前端受限数据缓存，处理返回历史页、恢复标签页与路由预取，避免旧画面闪现；无法收回已交付的字节。
- 不把资格凭据、认证 Cookie、测试答案或敏感正文写入 URL、分析事件与常规访问日志。
- 浏览器只展示必要的状态；账号导出与删除覆盖资格记录，不能遗留无法追溯的资格副本。

## 9. 数据与保留建议

建议分别保存内容分类、账号资格、题目与规则版本、测试尝试、会话显示模式及管理审计。

- 内容分类独立于上游资料导入，保存人工覆盖；刷新 VNDB / Bangumi 数据不得覆盖管理员判断。
- 资格记录包含账号、通过时间、规则版本、测试版本和授予来源；撤销记录包含理由及执行者，不包含心理标签。
- 有效尝试需保存题目集合与选项映射，以便服务端验证。已提交后保留时间、结果、错题 ID、版本和幂等标识，不长期保存逐项选择；测试明细建议 30 天后清理，长期资格依据保留至账号删除或资格废止。
- 失败限次按账号记录，退出重登不重置；结合现有请求限流抑制大量新账号或接口请求，不把 IP 当作心理或年龄证据。
- 清理不得影响滚动 24 小时限次、仍有效的尝试及正在处理的幂等请求。
- 资格更新与尝试结算在同一事务内完成；判分通过时重新检查当前规则版本和暂停状态。

## 10. 实施顺序建议

1. **分类与盘点**：列出页面、版本、图片、分享和所有资源映射入口；为现有目录核实分级，建立缺证据清单。先生成可审阅结果，不直接写生产。
2. **账号资格与题库**：接入现有会话，加入测试、资格、暂停和模式控制；不改变已部署游戏资源传输方式。
3. **统一公开投影**：接入 SSR、目录、搜索、标签、继续阅读、个人列表和分享；分离可信内部目录。
4. **启动边界**：接入播放器页、可信启动 HTML、资源清单和兼容入口。确认未获得资格时没有提前创建游戏 iframe、加载画面或播放声音。
5. **远程隔离验证与预览**：使用独立账号、数据库与索引；按项目规则在远程构建机持久化执行。预览不等于生产发布。

首版不包含新增敏感图库。题库扩展、可选的暴力和剧透偏好可以在核心准入稳定后继续设计。

## 11. 验收标准

### 准入与测验

- 游客、未通过、需重测、暂停资格、资格通过但未开启五种状态均不能取得站内受限投影和启动清单。
- 只有资格有效且当前会话主动开启时可访问；修改 URL、Cookie 中自报的开关或客户端分数不能授予资格。
- 双击、并发、网络重试、过期尝试、旧规则版本、暂停期间提交和跨账号提交结果一致且不重复计次。
- 测试文案不出现“认证成年”“心理合格”“心智成熟”等承诺；无敏感个人经历问题。

### 展示与隐私

- 匿名首屏、无 JavaScript 页面、客户端导航、直接链接、网页元数据与预取均无意外敏感展示。
- 搜索排序、分页、总数与标签统计符合当前模式；分类改动后旧索引候选仍由数据库阻止展示。
- 继续阅读、收藏与分享不泄露未经审核的敏感标题；关闭模式不删除原有记录。
- 退出、换账号、撤销设备、撤销资格、返回历史页和恢复标签页时收起受限内容；已经运行的游戏不会因切换模式而被静默销毁存档。
- 个人备份导出、恢复和删除不因失去浏览资格而失效。

### 资源与部署边界

- 枚举并验证站内清单、版本资源查询、兼容入口和资源索引，不存在另一条未经检查的应用接口可返回受限清单。
- 如加入敏感素材，其正文接口也必须受控，不能仅保护详情页。
- 资格检查通过后的游戏正文仍按既有 CAS 链路直连，主站不代理正文，不引入 Worker。
- 验收明确记录“现有公开哈希字节不受本资格撤回控制”，不得将站内准入测试表述为资源级防绕过或年龄验证通过。
- 发布前必须完成现有可见目录的分类与缺证据处理；没有核实的分类不默认为全年龄或 SFW。

## 12. 留给实现者的选择

实现者可按现有代码惯例决定具体表名、模块名、接口命名、索引结构与管理表单布局；保持上述状态、权限和证据含义不变。

最终题库逐题文案、规则版本号和重试参数在开发前随设计评审确认。第一期不接年龄核验，不生成心理评分，不改变公开 CAS 字节的权限模型。
