# oRPC 业务接口全面接入计划

**目标：** 用 oRPC 契约覆盖现有业务 JSON API 与浏览器调用，保留 REST URL、HTTP 方法、权限、审计、冲突控制和兼容客户端。

**架构：** Hono 继续承载安全中间件与 listener。oRPC OpenAPIHandler 处理现有路径的契约校验；已有领域服务继续作为业务实现。契约只引用浏览器安全的 schema / 类型，客户端通过 OpenAPILink 调用。兼容适配器复用已有 Hono handler，保留响应状态、Cookie、请求上下文；不得重新递归请求业务 app 或重复取全局锁。

**范围：** 目录管理、后台、账号自定义接口、书架、统计、内容资格、资料、存档控制和分享。Better Auth 原生接口、WebAuthn 恢复握手、二进制传输、CAS/资源协议、WS/WebRTC/WebTransport 保留协议；资源 JSON 查询在不破坏协议情况下接入契约。

**约束：** 本机只读改代码与轻量检查；安装、构建、全套测试与浏览器在 localhost-1 独立目录和持久化任务中执行。不得发布生产、推送、变更已有远程服务或业务数据。当前 worktree 已隔离，初始 HEAD 41c99d1，工作区干净。

## 重点风险

1. 查询不得因为迁移变为 POST 而进入写锁或新增 binding 要求。
2. Hono 中间件已经缓存请求体后仍须正确解析，Set-Cookie 与特殊状态码不得丢失。
3. 内容权限投影位于外层 fetch，契约和客户端不得泄漏未投影数据。
4. 保存提交的 409 响应仍须携带原有冲突数据，不能丢失本地待上传副本。
5. 兼容客户端保留既有错误码和审计行为，鉴权仍在服务端执行。

用户已在架构评估后明确要求“开始全面接入”，按以上业务范围持续执行，不重复提出试点或设计审批。实现分工仅按互不重叠的模块并行；共享注册器与最终集成由主代理负责。
