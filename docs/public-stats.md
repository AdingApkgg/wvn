# 公开统计与 Umami

目录和作品页显示阅读、点赞、收藏汇总；登录后的作品页可以点赞、收藏及撤销，账号书架显示“我的收藏”。收藏与阅读进度分别保存，不改写原书架、存档或历史版本。

## 计数口径

- 阅读：播放器接到经会话、来源窗口和游戏身份校验的 `started` 消息后上报。同一浏览器、同一作品的全部版本共用滚动 30 分钟去重窗口。它表示实际启动次数，不表示通关人数或独立用户人数。
- 访客：站点签名的随机 Cookie，服务端仅保存派生标识；新访客先取得 Cookie，再计数。浏览器 Web Lock 协调首次跨标签请求，SQLite 事务负责跨进程最终去重。
- 新统计身份签发另有持久配额：全站每 10 分钟最多 600 个，回环代理路径同样执行。触限返回 429，已有签名访客仍可使用；游戏、存档及账号注册不占这份配额。它限制简单重复换 Cookie 的灌量，不是独立用户或真人认证。
- 点赞、收藏：登录账号对作品的目标状态，重复提交幂等，撤销不会变负数。汇总由现存关系计算，账号注销会一并移除关系；账号导出包含自己的关系。
- 公开接口只返回汇总，不返回收藏者、点赞者或私人书架。失效版本不接受上报。
- DNT 开启时不自动上报；浏览器不支持 Web Lock 或统计请求失败时，游戏、存档及账号操作继续工作。

数据保存在既有账号 SQLite 的新增表中，原有完整数据库备份会自然包含它们。注销账本重放兼容旧备份缺少新增表，以及离线连接关闭外键的情况。

## 独立 Umami 服务

参考 [adx-dl 的部署与同源接入](https://github.com/adingApkgg/adx-dl/tree/5bfd20d4cc300a770a49199d467c9fcd70e1d318)，使用固定摘要的官方 Umami 3.4.0、PostgreSQL 18 镜像。配置见 `ops/analytics/compose.yaml`。

数据库只在内部网络；Umami 仅绑定 `127.0.0.1:18561`，另接前端 bridge 以发布该回环端口。独立 Compose project、数据库、卷和随机密钥不会复用业务账号库。初始化脚本替换默认管理员密码，凭据和临时令牌仅留在 Arch 的私有状态目录，权限为 0600。

账号服务的可选配置：

```dotenv
WG_UMAMI_WEBSITE_ID=<本实例中创建的网站 UUID>
WG_UMAMI_INTERNAL_URL=http://127.0.0.1:18561
```

二者必须同时配置。浏览器只得到公开网站 ID；后台地址、管理凭据、账号密钥均不会进入前端。未配置时不加载统计脚本。

同源 `/_s/` 代理仅提供 `GET /script.js` 和 `POST /api/send`，不经过账号事务锁。管理 API 均返回 404；上游失败有超时和通用错误，不暴露上游响应头、跳转或认证信息。

允许的路径仅为目录、作品和版本页。服务端重新构造事件：删除查询参数、片段和来源，标题固定为 WVN；事件只允许 `reading_start`、`like`、`favorite`，作品身份从公开路径推导。账号页、分享页、播放器内部资源和任意自定义数据均不接受。不会转发账号 Cookie、Authorization 或访客自行填写的 IP 头。

当前预览不恢复边缘代理后的公网客户端 IP，因此地理和独立访客指标不作精确依据；C 端阅读量使用自己的上述去重规则。正式环境接入可信边缘来源需另外验收，本轮不修改生产。

Umami 会忽略默认 Headless 浏览器流量。验收须同时检查事件实际落库，不能仅凭上报返回 200 宣称统计成功。

## 验收

远程执行 `scripts/verify-public-stats.mjs`，使用虚拟通行密钥和独立合成账号，覆盖登录关系、撤销、刷新、收藏列表、导出、注销、真实启动、私页、移动端、DNT 和代理边界。账号清理放在 `finally`，失败回执保留错误阶段和截图。

`scripts/verify-reading-tabs.mjs` 另测双标签首次启动和统计脚本被拦截时的实际游戏、保存操作。数据层另有两个真实 Node 进程同时请求同一 SQLite 的去重测试。

Tyrano 必须配置、已解析的场景标签和原生执行指针实际就绪后才发出 `started`。`scripts/verify-tyrano-startup.mjs` 用真实场景请求阻断验证失败不计数，并在恢复后验证滚动去重。
