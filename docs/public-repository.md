# 公开仓库与私有配置

WVN 的公开仓库只保存应用源码、目录元数据、引擎锁和构建配方。游戏资源、引擎构建输出、真实账号数据、Passkey 服务端配置、云存档、审核令牌和运行日志在部署侧独立维护。

## 脱敏范围

公开历史中的个人内网主机和设备名已替换为示例名称；内网地址使用 `192.0.2.0/24` 文档示例网段，个人工作目录使用 `/Users/developer` 和 `/home/wvn`。提交作者使用 GitHub 的 noreply 地址。涉及其他项目本地源码的内部规划材料与生成式部署清单不进入公开历史。

这些示例主机和地址不指向可用服务。历史验收文档保留技术边界，不应当作当前生产拓扑或可直接执行的部署指令。部署脚本中的主机、路径检查仍然保留，必须按自己的隔离环境适配。

`/home/web_user/.renpy` 等路径属于游戏运行时的文件系统或旧档身份，并非宿主机个人目录，继续保留以维持存档兼容。

## 私有文件

`.gitignore` 排除环境文件、私钥、账号数据库、备份、`state/`、`reports/`、依赖和构建输出；`.env.example` 只说明配置项，不包含凭据。服务端密钥通过独立文件注入，账号和存档不应复制进仓库，也不应作为公开测试 fixture 使用。

公开内容检查可执行：

```sh
python3 scripts/audit-public-repository.py --history
```

该检查遍历 Git 可达历史和已跟踪的待提交文本，只输出命中文件及规则名，不输出命中的内容。它帮助识别常见令牌、私钥、个人目录和内网地址，不能证明任意秘密都不存在，提交前仍需检查差异。

仓库公开不改变线上服务配置；发布应用、迁移数据库、更新引擎与验证真实存读档仍各自独立进行。原发布的提交编号在历史清理后可能变化，部署回执应继续按实际源清单和产物校验值核对。
