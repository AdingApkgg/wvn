## 总体判断

目前已有深色暖金主题、标准按钮与表单组件、移动底部导航和版本独立存档保护。主要问题是这些能力按技术模块堆叠，尚未形成围绕读者任务的一致操作逻辑。

读者需要同时理解“收藏与私人书架”“账号分区与全局导航”“游戏内保存、本机副本与云备份”“资格与显示模式”。其中部分概念必须保留，但应在需要时解释，并为每个状态提供一个明确的下一步。

以下为专家启发式审计，未进行真实用户访谈或可用性测试，不能把推断表述为量化用户研究结论。

## 优先问题

| 优先级 | 发现与证据 | 对用户的影响 | 建议 |
| --- | --- | --- | --- |
| P1 | `src/root.tsx` 提供站点页头，`src/routes/share.tsx` 又自行渲染页头；匿名分享页桌面与手机均检测到 2 套 | 同一页面出现两组品牌、账号与返回入口 | 公开页面只使用一个站点壳层 |
| P1 | 390px 作品页截图中标题与编号重叠，互动区域被限制在封面宽度的窄列；移动 grid 与 `display: contents` 未完整分配新增子区域 | 可读性下降，点赞、收藏和说明占据大量纵向空间 | 重新定义移动首屏区域，标题与编号分行，互动和操作占完整内容宽度 |
| P1 | 全局“书架、存档”和账号内部“书架、存档、我的分享、账号安全”重叠；账号入口只有图标 | 用户难以判断自己在什么分区，分享与设置入口不明显 | 一级任务导航固定，页内只保留当前任务的子导航 |
| P1 | `library.tsx` 同时放收藏、搜索全站作品、下拉选作品、添加、每本书的状态/笔记/版本表单 | 找到“继续阅读”之前要越过大量编辑控件 | 阅读列表优先，编辑按需展开；添加从作品页和可搜索选择器发起 |
| P1 | `ons/player.tsx` 的“保存并退出”提取已有存档文件并停止实例，仍留在播放器页 | 容易误以为保存了当前剧情，或已经返回作品页 | 明确命名“结束阅读”，分别反馈游戏存档、本机副本与云备份 |
| P1 | 账号云备份先要求从全站版本下拉选择，再理解引擎档案；播放器另有云备份入口 | 用户要先记住版本和技术身份，才能找备份 | 以作品分组显示已有备份，保留版本/档案身份；从播放器进入时直接带入当前上下文 |
| P1 | 手机浏览设置页先显示完整规则与测试说明，登录和实际下一步位于后面，截图可见 | 用户在长文中寻找如何继续 | 首屏先显示当前状态、步骤和下一步；规则在测试前可完整阅读 |
| P2 | 发现卡片同时突出引擎、编号、版本数、阅读/点赞/收藏数字及“阅读详情” | 选择故事被技术与运营信息打断 | 强调封面、标题、简短描述及必要内容提示，其他信息降低层级 |
| P2 | `work.tsx` 默认阅读目标与全部版本、检查记录、引擎信息并列；本地版本目标不一定等于当前可启动目标 | 用户担心选错版本或影响存档 | 只推荐可启动版本；版本切换时清楚说明存档分开保留，检查记录置于详情 |
| P2 | 实测作品顶部显示“取得资格后阅读”，同页版本列表仍显示“阅读版本 N”；简介将原文和已有中文整理连续全部铺开 | 同一任务的状态不一致，阅读到下一操作需要长距离滚动 | 所有入口共用可启动状态；已有中文简介默认展示，原文按需展开并保留来源 |
| P2 | 点赞/收藏登录跳到通用账号页，`account.tsx` 没有统一处理操作返回目标 | 登录后需要自己找回原作品和任务 | 统一安全的站内返回目标，返回后保留上下文，不静默替用户执行写入 |
| P2 | 公开浏览入口约 17–18px 高，账号图标约 38px 高，登录按钮约 36px 高 | 手机操作需要精确点击 | 本项目统一采用 44px 的主要触控目标；不据此直接宣称未通过 WCAG AA |
| P2 | 新匿名会话会看到“关闭旧版游戏页面”的升级提示 | 首次使用者也需理解历史迁移和进行确认 | 只有检测到相关旧上下文或实际阻碍时才显示必要操作；保留真实的隔离升级保护 |
| P2 | 标准弹窗与 `window.confirm` 混用，状态与错误消息位置分散 | 同类操作的反馈和取消行为不一致 | 统一确认、就地错误、状态摘要、焦点恢复和待处理反馈 |
| P2 | 后台将大量作品编辑表单与嵌套折叠层叠放，资格/分享/目录审核分处不同模块 | 管理人员切换对象时容易失去上下文 | 保留权限边界，以列表→当前对象→编辑/审核的稳定结构组织 |

## 设计系统现状

当前资格分支的 `src/styles.css` 为 1384 行，检出 62 处十六进制色值、49 个不同值、9 个媒体查询段。颜色包含必要的主题、封面装饰和播放器遮罩，不能把所有出现次数都当作缺陷。

| 类别 | 已有基础 | 需要补齐 |
| --- | --- | --- |
| 颜色 | background、foreground、card、primary、muted、destructive 等语义变量 | success、warning、info，以及加载/遮罩对语义 token 的复用 |
| 字体 | 系统中文字体、衬线品牌、响应式标题 | 固定的正文/辅助/标题比例，减少 8–11px 的关键操作文字 |
| 间距与布局 | 容器、卡片、grid、移动断点 | 统一间距尺度、阅读与表单宽度、页面与分区标题 |
| 按钮 | 主、次、描边、幽灵、危险变体及禁用态 | 触控尺寸、异步处理中说明、主次动作使用规则 |
| 输入与选择 | Label、Input、Textarea、NativeSelect | 明确已修改/保存中/已保存/冲突状态，版本选择与任务上下文结合 |
| 反馈 | Alert、AlertDialog、role=status、加载覆盖层 | 同类任务共享反馈位置与术语，持续错误不能只短暂出现 |
| 导航 | 桌面顶栏、手机底栏、账号 Tabs | 单一当前分区、深链接兼容、统一公开页面壳层 |
| 文档 | 部分历史验收与功能说明 | token、组件状态、页面模式和操作文案的统一规范 |

## 阅读截图时的边界

全页截图不会保证所有懒加载图片都已触发加载。不能由离屏区域的空白推断线上封面丢失。尺寸扫描仅用于定位需要复核的控件，也不替代完整的目标尺寸、焦点、屏幕阅读器与对比度验收。

## 采用的依据

- [Nielsen 可用性原则](https://www.nngroup.com/articles/ten-usability-heuristics/)：本审计重点应用状态可见、与用户语言一致、减少记忆和错误恢复等原则。
- [W3C 文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)：实施验收需要测量普通文字至少 4.5:1、大文字至少 3:1，而不是仅凭截图判断。
- [W3C 增强目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html)：44×44 CSS px 对应增强目标尺寸；本项目将它作为主要触控控件的设计目标，不混称为 AA 最小标准。

完整的建议行为、页面结构及验收标准见 [设计系统规范](design-system.md)。
