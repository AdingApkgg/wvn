# B2 预览读取与 RenPy 音视频兼容

资源迁移的对象摘要一致，只能证明复制完整；游戏能否运行还需要浏览器实际加载、正文推进和退出后重进验证。预览与生产切换分别验收，原资源继续保留。

## 共享 RenPy 音视频停止

固定共享版本 `renpy-5b572ebfa6248cac249cab61f698c967cac82b7d225da7515971b383d0f0a3cf` 的 `video_stop` 会无条件读取播放对象的 `draw_stats[1]` 和 `file_stats[1]`。普通文件队列没有这两个统计字段，停止片头时会抛出异常，后续媒体元素清理无法完成。

`public/player/renpy-audio.mjs` 在数据预载完成、原生初始化回调执行前，只对沙箱内存文件系统中的 `/renpy/common/_audio.js` 增加两个可选字段判断。停止、资源清理和下一段队列逻辑保持原样；B2 引擎文件和原始源码归档不变。

适配仅匹配上述共享版本和已知源码结构。旧版引擎直接跳过，重复调用不重复写入，未知源码结构拒绝修改。回归夹具保留上游 MIT 许可，覆盖原异常、资源释放、下一段队列和原有 FPS 诊断。

## 完整读取与响应头期限

`scripts/lib/read-verified-resource.mjs` 提供两个只读工具，供隔离预览网关调用：

- `readVerifiedResource` 将响应头、完整响应体及 SHA-256 校验视为一次尝试。网络中断、响应体停滞和服务端临时错误最多尝试三次；404、超限和摘要不符直接拒绝。截断数据不会返回调用方，调用方取消会终止重试。
- `fetchResourceHeaders` 只在等待响应头时计时，收到响应头后清除该期限。持续下载的大文件不会被旧的响应头计时器截断；调用方的取消信号在正文传输期间仍然有效。

本轮私有预览网关还合并相同引擎读取，并用有上限的内存缓存复用已验证字节。字体也在向浏览器发出响应前完整读取、核对 B2 SHA-1，单文件上限 32 MiB，与引擎共用 96 MiB 缓存上限，避免转发开始后的断流直接暴露给浏览器。校验失败不会入缓存，失败的入口或清单请求不会永久缓存为失败。游戏包和媒体保持流式只读读取。

## 验证范围

在专用远程主机执行以下定向测试，共 36 项：

```sh
node --test tests/verified-resource-read.test.mjs \
  tests/renpy-audio-compat.test.mjs \
  tests/emscripten-runtime.test.mjs \
  tests/engine-adapters.test.mjs
```

网络回归使用真实 HTTP 服务制造收到 200 响应后的断流、正文停滞和延迟响应，并验证取消与重试上限。浏览器回执另行记录启动、实际画面或正文、重进、资源来源和异常，不能用启动事件替代完整游玩验收。

私有预览网关另有 4 项隔离集成回归，在远程主机使用合成字体和回环 HTTP 服务验证断流重试、真实 SHA-1 差异、读取上限，以及 HEAD、Range、ETag 和缓存行为，不请求真实 B2 对象。

本轮修改不包含生产资源地址切换，也不写入 B2 对象或用户账号与云存档。
