# 播放器启动、缓存与存档优化

## 实现与验证计划

1. 抽出启动资源准备器，默认两路并发，64 MiB 预算，大于预算的对象独占；覆盖并发、预算、取消、失败停止派发。
2. 下载器区分前台与后台优先级，调度器通过动态回调传递提升状态；覆盖前台请求和后台提升。
3. OPFS 视图在完整摘要核验后登记模块私有证明，仅同一 Blob、SHA 和大小可复用，其他缓存仍完整校验；覆盖命中与损坏拒绝。
4. 新视图使用独立会话目录，以浏览器 Web Locks 作为存活租约；仅回收能取得独占锁的旧会话。无锁能力时不自动回收，旧平铺视图保留给显式清理，避免误删旧页面资源。覆盖活动会话、崩溃遗留及无锁降级。
5. 摘要计算复用同步结构检查，在首次 await 前向 WebCrypto 提交全部文件，避免额外整份快照复制，同时保持调用时字节语义；覆盖调用后修改、格式拒绝和云备份往返。

采用局部修改，沿用现有资源/存档边界。浏览器锁比定时续约更适合临时视图：后台冻结不会被误判成租约过期，页面崩溃后锁由浏览器释放。

测试先加入回归并确认失败，再实现。针对性测试、播放器模块回归、类型检查和构建在 Debian 专用构建机的独立目录及 tmux 任务中执行，保存退出码。实际游戏首帧速度和三浏览器行为需独立验收，单元测试与构建不能代替。
