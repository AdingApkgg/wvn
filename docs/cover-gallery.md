# 自适应封面墙

首页按图片的宽高比进行等高混排，封面、方图和横图保留完整内容。普通卡片使用 Flex 按比例分配行内宽度，文字位于图片外；卡片顺序与搜索结果顺序一致。最后一排吸收余量，避免只有一部作品时把封面放大到整行。

Logo 和宽高比超过 2.2 的图片使用横向卡片，图片与文字并排。手机上普通竖封面通常每排两张，横图通常单独成排。图片统一 contain，极窄图片保留完整内容并适量留边。

已有宽高元数据用于首屏布局；缺少尺寸时先使用按图片类别设定的比例，加载后按实际尺寸调整。未知尺寸的图片加载时可能发生局部重排。无 JavaScript 时仍保留完整图片与可用的搜索表单。

## 2026-11-11：UI 重设计后的约束回归修复

UI 重设计误将封面墙改为统一列数与 2:3 容器，并删除实际图片比例更新和横卡识别。现恢复原 Flex 混排、末行余量保护和 Logo/超宽图横卡，保留新的导航与交互样式。图片加载事件之外，挂载时也读取已加载图片的实际尺寸，覆盖缓存或快速响应早于 hydration 的情况。极窄图片继续沿用既有留边规则。

远程隔离验证先复现 3 项真实布局失败，修复后通过全库类型检查、生产构建、11 项相关单元测试及 21 项 UI 浏览器测试（4 项封面检查、17 项阅读体验检查），无跳过。几何测试使用按目录元数据生成的合成图片，另验证实际方图/横图覆盖旧元数据、无 JavaScript 首屏比例；Logo 即使加载为方图也保持横卡，由专用单元约定保护。这些结果不代表全量线上图片可用性或完整游戏游玩验收。

后续 UI 验收统一运行 `npm run test:e2e:ui`，同时包含封面墙与阅读体验测试，不再只选新增用例。本记录描述隔离预览结果，不代表生产已更新。
